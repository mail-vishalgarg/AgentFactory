Data model & logic

One table. No separate tenants table — users.id is the tenant boundary.

users

columntypenote
iduuid pktenant key everywhere else
emailtext uniquelogin identity
password_hashtextbcrypt, cost = 10
is_adminboolseeded true for admin@capstone.com
created_at / updated_attimestamptz

Logic

  • Signup — password validator rejects weak passwords before hash_password ever runs.
  • No enumeration leak — wrong password and unknown email hit the same code path, same message.
  • Token — HS256 only; decode pins algorithms=["HS256"] explicitly.
  • Authorization — is_admin is always re-read from Postgres, never trusted from the token payload.
Key insight: "one user per tenant" means users.id is the tenant boundary — there's no multi-user-per-company model, so every owner_id filter across the schema is a "mine vs. not mine" check, not a "my company's vs. not" check.
