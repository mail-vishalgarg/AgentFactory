📦 Complete Single-Column Vertical Flow (Boxes & Moving Arrows)

Linear top-to-bottom vertical progression with code bindings, status checks, and moving laser lines:

1. User / Admin Visits Platform Login Page LoginPage.tsx
POST /auth/login { email, password }
Enters email address and password. Submits to FastAPI authentication gateway.
Bcrypt Hash Verification
2. Database Authentication & Role Check users.is_admin
SELECT id, email, hashed_password, is_admin FROM users WHERE email = ?
Checks password hash. Identifies whether the account is a Standard User (is_admin: false) or Platform Administrator (is_admin: true). Mints signed HS256 JWT.
Track 1: Standard Workspace User Path
3A. Lands on MCP Registry Page MCPRegistry.tsx
GET /mcp/servers (is_approved = true)
User sees the catalog of MCP servers that are already approved and published by the Admin (GitHub, Slack, GitLab, Jira, Postgres).
First Time / PAT Setup
4A. Connections Page (Encrypted PATs) Connections.tsx
POST /connections/validate & save
User clicks PAT link on MCP Registry:
  • Inputs personal access tokens (GitHub, Slack, GitLab, Tavily).
  • Live synchronous API test probe verifies keys immediately (/user, auth.test).
  • Tokens are encrypted in DB and MASKED in UI (hidden from view).
Navigate to Builder
5A. Agent Builder Page AgentBuilder.tsx
POST /agents { name, prompt, tools }
User builds custom agent based on requirements:
  • Writes custom System Prompt and instructions.
  • Selects required MCP servers and tools from the approved catalog.
  • Deselects tools that are NOT required (preventing tool sprawl).
Check Tool Tokens
6A. Token Interruption & Resume Gate Pause & Resume
GET /connections/check?tools=selected
System checks if tokens exist for all selected tools:
  • If token missing: Creation flow is INTERRUPTED (paused); modal prompts user for token.
  • User inputs token ➔ verified on the spot.
  • RESUMES immediately once token is provided!
Persist Agent
7A. Agent Created ➔ My Agents Dashboard MyAgents.tsx
GET /agents (owner_id = user.id)
Agent is saved in PostgreSQL and appears in user's "My Agents" dashboard.
Click Agent Card
8A. Agent Overview Tab (Backend Flowchart) AgentDetail.tsx
GET /agents/:id/overview
Displays visual flowchart showing how the agent is actually working in the backend (ReAct orchestration loop, active MCP tool bridges).
Open Testing Tab
9A. Playground Testing Tab Playground.tsx
POST /chat/stream (SSE Multi-Turn)
User tests whether the agent is working correctly or not:
  • Enters custom prompts and verifies real use cases.
  • Backend injects user's PAT JIT (zero secrets passed to the LLM).
  • Human-in-the-Loop: Destructive/write actions pause and prompt user for approval.
Evaluate Execution Metrics
10A. Automated Scoring Engine scoring.py
calculate_agent_score(agent_id)
Evaluates agent based on parameters:
  • Tool Scope: Penalizes tool sprawl / unused tools.
  • Prompt Completeness: Evaluates prompt length and structure.
  • Playground Reliability: Checks run success rate.
  • Computes Score (0–100) and Letter Grade (A–F).
Submit for Publishing
11A. User Submits Agent for Publishing publish_graph.py
POST /marketplace/publish
LangGraph checkpointer invokes interrupt(); review state is durably saved in PostgreSQL.
Track 2: Platform Administrator Governance Path
3B. Admin Identified & Registers MCP Server Admin Authority
POST /mcp/register { name, url, provider }
Admin has exclusive authority to add servers. Selects/inputs server details, SSE/stdio endpoint URL, and provider.
Live Handshake Test
4B. Test Server with Admin's PAT POST /mcp/test-probe
Live probe using Admin's own PAT credentials
Admin tests whether the server is working properly or not by supplying their own PAT token. Validates connectivity and tool introspection.
Approve Globally
5B. Approve & Publish Server to Entire Website Global Availability
UPDATE mcp_servers SET is_approved = true
Server is approved and published. Instantly visible to all users on the MCP Registry page!
Convergence: Admin Review & Score 70 Threshold
12. Admin Review Portal AdminReview.tsx
GET /marketplace/submissions/pending
Admin inspects pending agent submissions, prompt safety checklist, tool bindings, and the automated score (0–100).
Score 70 Decision Gate
13A. REJECT (Score < 70) Command(resume="rejected")
STATUS = 'rejected'
If score is below 70, Admin rejects. Sent back to user with feedback to improve prompts or reduce tool sprawl.
Score >= 70 (Passing Threshold)
13B. APPROVE (Score >= 70) ➔ Published to Marketplace! Marketplace.tsx
STATUS = 'published' | is_public = true | Command(resume="approved")
Agent is officially published with Trust Badge, Score, Grade, and Tool Manifest.
Direct Ecosystem Reuse
⚡ 14. DIRECT AGENT REUSE (Zero Rebuilding Required!) Community Value
POST /marketplace/install/:id
Any user on the platform can now discover and use this agent directly without building it again! Clicks "Install Agent" and executes immediately with their own personal connected PAT tokens.
