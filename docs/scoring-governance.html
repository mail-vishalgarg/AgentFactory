The Publish Gate — three independent checks, AND-ed

Never blended into one opaque number — a perfect score with ungated write tools still can't publish.

blocked_reason names the first failing check — never a vague "can't publish."

Data model

No dedicated table. Everything below is recomputed live, on every request.

sourcefeeds
agents.config (jsonb)tools[].permission_level / requires_approval, description, system_prompt → score + governance
agent_runscount(*), count(status='ok') → reliability + coverage
agents.credentials + mcp_servers.statustrust checklist only — not scored

Trust checklist (surfaced, not scored)

  • Write/destructive tools require approval (reuses Signal 3)
  • Every attached MCP server reports status == "healthy"
  • No stored credential value appears inside the prompt or any tool description — a live substring scan, not an assumption
  • Tested N times in the playground (run_count)

Worked example — github_agent, live data (2026-09-19)

inputs        26 tools (all read) · 2/2 runs ok · description 17 chars
reliability   round(2/2 × 40 × min(1, 2/5)) = round(40 × 0.4)        = 16
scope         30 − (25 extra tools × 1/read)                        =  5
coverage      round(min(15, 6) × 1.0)                                =  6
completeness  desc<20 (+0) + prompt≥20 (+5) + has tools (+5)         = 10
─────────────────────────────────────────────────────────────────────────
total         16 + 5 + 6 + 10                                       = 37 / 100
Key insight: score and governance are deliberately never combined into one number. A perfect score with ungated write tools still can't publish, and a perfect governance grade on a broken agent still can't either — Rule 6's "a score that blocks nothing is decoration" is enforced structurally, not by convention.
