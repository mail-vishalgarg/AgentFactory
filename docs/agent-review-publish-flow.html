Logic

  • Real interrupt, not simulated — interrupt() genuinely suspends the coroutine; "pending" isn't faked with a plain status column alone.
  • Session-mode pooler required — AsyncPostgresSaver's pipelined writes break against Supabase's transaction-mode pgbouncer (:6543); the checkpointer uses the session-mode pooler (:5432) instead.
  • thread_id is the join key between the queryable row and the actual paused graph state.
  • Rule 5 enforced at creation — the sanitized tool snapshot is built once, before the graph ever runs.
  • Pool hardening — max_idle=180 + check=AsyncConnectionPool.check_connection, since Supabase silently closes idle connections.
  • The one deliberate isolation exception — admin routes read every owner's rows, gated entirely by require_admin.
Key insight: the pause is real, not simulated — verified by killing the backend process mid-pause and resuming successfully after a fresh restart. thread_id is what makes that possible: a stable pointer into Postgres-backed state that outlives the Python process.
